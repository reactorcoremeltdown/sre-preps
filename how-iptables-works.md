# **Understanding How `iptables` Works**  

`iptables` is a **packet filtering** and **firewall tool** built into the Linux kernel, specifically as part of the **netfilter** framework. It allows system administrators to define **rules** that control how packets are handled by the network stack.

## **1. How `iptables` Works at a High Level**
- `iptables` operates at the **kernel level** and **intercepts packets** traveling through different **network chains**.
- It applies rules **sequentially** until a **matching rule** is found.
- If no rules match, the packet is handled by the **default policy** (ACCEPT or DROP).

## **2. The Packet Flow in `iptables`**
`iptables` operates in **five chains** that process packets depending on their direction:

### **Chains in `iptables`**
| Chain | Function |
|-------|----------|
| **PREROUTING** | Alters packets **before routing** decisions are made. Used for DNAT (Destination NAT). |
| **INPUT** | Handles packets **destined for the local system** (e.g., SSH, HTTP requests to the machine). |
| **FORWARD** | Handles packets **passing through** the system (e.g., a router/firewall forwarding traffic). |
| **OUTPUT** | Handles packets **generated by the system**. |
| **POSTROUTING** | Alters packets **after routing**, just before sending them out. Used for SNAT (Source NAT). |

### **Visualizing Packet Flow**
```
            Incoming Packet
                  |
                  v
         +-----------------+
         |  PREROUTING     | <--- DNAT happens here
         +-----------------+
                  |
                  v
    +--------Routing Decision--------+
    |                                |
    v                                v
+------------+                +------------+
|   INPUT    |                |  FORWARD   |
| (Local Use)| --------------> | (Forward) |
+------------+                +------------+
                                     |
                                     v
                             +------------+
                             | POSTROUTING| <--- SNAT happens here
                             +------------+
                                     |
                                     v
                               Outgoing Packet
```

## **3. Tables in `iptables`**
`iptables` consists of **multiple tables**, each serving a different function.

| Table | Purpose |
|--------|---------|
| **filter** | Default table, used for packet filtering (ACCEPT, DROP, REJECT). |
| **nat** | Handles **Network Address Translation (NAT)** like **DNAT** (port forwarding) and **SNAT** (masquerading). |
| **mangle** | Modifies packet headers (e.g., TTL, QoS settings). |
| **raw** | Used for marking packets before `conntrack` (connection tracking). |
| **security** | Enforces SELinux security policies. |

By default, rules are applied to the `filter` table unless specified otherwise.

---

## **4. Rules in `iptables`**
Each **chain** consists of **rules** that determine how packets are handled.

### **Rule Structure**
```
iptables -A <CHAIN> -s <SOURCE_IP> -d <DEST_IP> -p <PROTOCOL> --dport <PORT> -j <TARGET>
```
- `-A` → Append rule to a chain.
- `-s` → Source IP.
- `-d` → Destination IP.
- `-p` → Protocol (`tcp`, `udp`, `icmp`).
- `--dport` → Destination port.
- `-j` → Jump to a target (`ACCEPT`, `DROP`, `REJECT`, `LOG`).

---

## **5. Targets in `iptables`**
Targets determine what happens to a packet when a rule matches.

| Target | Description |
|--------|-------------|
| **ACCEPT** | Allow the packet to pass. |
| **DROP** | Silently discard the packet. |
| **REJECT** | Discard the packet and send an error response. |
| **LOG** | Log the packet details before passing to another rule. |
| **MASQUERADE** | Used in NAT for outgoing traffic (hides internal IP). |
| **DNAT** | Changes the destination address of a packet (used for port forwarding). |
| **SNAT** | Changes the source address of a packet (used for internet access). |

---

## **6. Common `iptables` Examples**
### **(A) Allow Incoming SSH Traffic**
```sh
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```
- Allows **TCP traffic** on port **22** (SSH).

### **(B) Drop All Incoming Traffic Except SSH**
```sh
iptables -P INPUT DROP
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```
- Sets the **default policy** for `INPUT` to **DROP**.
- Allows only **SSH traffic**.

### **(C) Enable NAT (Masquerade) for Internet Sharing**
```sh
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```
- **NAT (MASQUERADE)** allows internal LAN clients to share an external IP.

### **(D) Port Forwarding (DNAT)**
```sh
iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.100:80
```
- Redirects **incoming traffic on port 8080** to **192.168.1.100:80**.

---

## **7. Connection Tracking (`conntrack`)**
Linux **tracks active connections** using **connection tracking** (`conntrack`).

### **Enable Stateful Firewall (Allow Related and Established Connections)**
```sh
iptables -A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
```
- Allows packets that belong to **existing connections** (e.g., SSH replies).

---

## **8. Listing and Managing Rules**
### **(A) View Rules**
```sh
iptables -L -v -n
```
- `-L` → List rules.
- `-v` → Verbose output.
- `-n` → Show numeric IPs/ports (avoid DNS resolution delays).

### **(B) Save and Restore Rules**
```sh
iptables-save > /etc/iptables.rules
iptables-restore < /etc/iptables.rules
```
- Saves and restores firewall rules.

### **(C) Flush (Clear) All Rules**
```sh
iptables -F
```

---

## **9. `iptables` vs. `nftables`**
Linux is moving towards **`nftables`**, a modern replacement for `iptables`.

| Feature | `iptables` | `nftables` |
|---------|-----------|------------|
| Performance | Slower | Faster |
| Syntax | Complex | Simplified |
| Stateful | Yes | Yes |
| IPv4/IPv6 | Separate rules | Unified rules |

To check if `nftables` is used:
```sh
nft list ruleset
```

## **10. Real-World Use Cases**
1. **Blocking Malicious IPs**
   ```sh
   iptables -A INPUT -s 203.0.113.5 -j DROP
   ```
   - Blocks traffic from `203.0.113.5`.

2. **Rate Limiting SSH (Prevent Brute Force)**
   ```sh
   iptables -A INPUT -p tcp --dport 22 -m limit --limit 3/min -j ACCEPT
   ```
   - Limits SSH login attempts.

3. **Load Balancing Between Two Web Servers**
   ```sh
   iptables -t nat -A PREROUTING -p tcp --dport 80 -m statistic --mode nth --every 2 --packet 0 -j DNAT --to-destination 192.168.1.10:80
   iptables -t nat -A PREROUTING -p tcp --dport 80 -m statistic --mode nth --every 2 --packet 1 -j DNAT --to-destination 192.168.1.11:80
   ```
   - Distributes traffic evenly between two servers.

---

## **Conclusion**
- `iptables` is a **powerful firewall** and **packet filtering** tool.
- It processes **packets using chains and tables**.
- `iptables` rules are **applied sequentially**.
- **Stateful filtering** is achieved using `conntrack`.
- **Alternative:** `nftables` (faster, simpler).

This knowledge is **crucial for SREs and DevOps engineers** handling Linux networking! 🚀
